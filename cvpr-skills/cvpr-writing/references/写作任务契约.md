# 写作任务契约

## 模式

| 模式 | 必需输入 | 主要输出 |
|---|---|---|
| `argument_and_outline` | IDEA、Goal、Result 或独立材料、Claim 列表 | 中心论断、贡献链、章节提纲 |
| `section_draft` | 目标章节、相关 Claim 与证据 | 指定章节草稿 |
| `full_draft` | 已确认提纲、完整证据包 | 完整初稿及缺口表 |
| `evidence_based_revision` | 原稿、修改请求、新旧证据引用 | 修订稿和逐项变更记录 |

`completed` 表示约定范围内的写作任务完成，不表示论文通过审计或达到投稿状态。

## 项目模式

- `cvpr_project`：必须引用非空 `snapshot_ref`、`.cvpr/result.yaml` 和 `.cvpr/claims.yaml`。
- `standalone`：允许只使用用户提供材料，但必须填写 `scope_note`，说明没有检查哪些上游证据。

所有输入和输出使用项目根目录相对路径、稳定 ID 或提交引用，不使用无法追溯的“上面的结果”等表述。

## 状态

- `proposed`
- `drafting`
- `completed`
- `blocked`
- `superseded`

`blocked` 必须登记阻断项。`completed` 不得含核心证据缺口、`prohibited` Claim、未确认的完整初稿提纲或未追溯数字。

## 修订

`evidence_based_revision` 必须逐项记录：

- 修改位置；
- 修改原因；
- 输入证据或用户决策；
- 原论断与新论断；
- 是否改变证据强度；
- 受影响的术语、数字、图表或引用。

若新证据改变 Result 结论，停止写作并返回上游，不在正文内自行改判。
