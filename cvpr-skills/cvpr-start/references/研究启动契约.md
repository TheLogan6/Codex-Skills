# 研究启动契约

## 目的

`.cvpr/start.yaml` 是研究启动阶段的机器可读权威记录。它保存种子输入、补充文献、问题状态、候选 IDEA、独立审查、用户讨论和最终 IDEA。`project.yaml.working_idea` 只能保存当前摘要，不能代替本契约。

该文件也是科研自我纠正循环的入口。`cvpr-result` 返回 `restart-idea` 时，必须同时引用失败证据包和原 `start.yaml` 中全部候选，不得只保留最终被选择的 IDEA。

## 根字段

```text
schema_version
start_id
version
status
created_at
updated_at
input
literature
user_material_check
problem_statuses
candidates
someagents_review
discussion
final_idea
blockers
supersedes
```

状态允许：

- `proposed`：已经建立任务，但证据尚未完成；
- `in_progress`：正在进行分析、检索、审查或讨论；
- `needs-reframing`：五轮实质讨论后仍未收敛，或现有问题需要重构；
- `accepted`：最终 IDEA 已由用户明确确认，全部强制门禁通过；
- `blocked`：全文、近期文献、候选、审查或关键输入存在阻断；
- `superseded`：被后续研究启动契约取代。

## 文献记录

`literature.added_papers` 只登记相对种子集合新增的论文。计入最低数量的论文必须同时满足：

- 身份和版本已经核验；
- 与当前问题直接相关或提供实质支持；
- 位于当前声明的时效窗口内；
- 至少有一个正文、附录、表格、图、公式或失败案例定位；
- 没有与另一版本重复计数。

经典锚点论文可以保留，但不能用来替代至少 10 篇足够新的新增论文。

## 候选 IDEA

每个正式候选必须满足 `候选IDEA证据卡.md`。机器记录至少保留：

- 唯一 `idea_id`；
- 研究问题、核心假设、拟议改动和预期机制；
- 至少两篇独立论文的实物证据，其中至少一篇近期论文；
- 反证、现有解决方案、新颖性边界、证伪测试和风险；
- 多 Agent 审查结论；
- 当前状态。

被拒绝、未选择或被后续证据否定的候选仍保留。不要从历史中删除。

## 多 Agent 审查

`someagents_review` 必须记录：

- `mode: B`；
- 所有 Agent 共同读取的 `input_snapshot_id`；
- 至少两个确实独立完成的 Agent 结果；
- 五个审查轴的完整覆盖；
- 少数意见、阻断项和最终协调结论。

五个轴是：

```text
source_recency
problem_evidence
novelty_related_work
method_falsifiability
feasibility_review_risk
```

不能用单 Agent 自我扮演多个角色，也不能在实际没有创建独立 Agent 时填写完成记录。

## 讨论与确认

`discussion.substantive_rounds` 只统计首次正式呈报后的实质讨论，最多为 5。每轮保存用户约束、系统回应、决策和证据引用。

`accepted` 必须满足：

- 至少 10 篇新增合格近期论文；
- 至少 5 个通过证据和审查门槛的正式候选；
- 多 Agent 审查完整且无未解决阻断；
- 最终 IDEA 引用其中一个 `user_selected` 候选；
- 用户明确确认最终 IDEA；
- 初步验收目标、边界和反证条件非空；
- 文件通过确定性校验。

## 自我纠正循环

从 Result 返回时，`input.kind` 使用 `failure_evidence` 或 `mixed`，并填写：

- `input.failure_evidence_ref`；
- `input.previous_start_ref`；
- `input.reused_candidate_refs`。

新一轮使用新的 `start_id`，通过 `supersedes` 指向上一轮。失败的 Goal、Plan、Run、Result 和候选 IDEA 均保留。
