# CVPR 研究启动

## 定位

本 Skill 将“课题”和“IDEA”合并为统一研究启动阶段，不设置脱离证据的形式门禁。它可以承接 `cvpr-init`，也可在用户直接给出范围或种子论文时独立启动。

该阶段只负责把研究方向收敛为一个有证据、可证伪、可执行且可验收的 IDEA。后续代码、实验、数据统计和论文写作由其他阶段承担。

## 必读规范

开始前读取：

- [启动流程.md](references/启动流程.md)
- [候选IDEA证据卡.md](references/候选IDEA证据卡.md)
- [多Agent审查协议.md](references/多Agent审查协议.md)
- [五轮讨论规范.md](references/五轮讨论规范.md)
- 创建、恢复或循环修订长期研究启动状态时读取 [研究启动契约.md](references/研究启动契约.md)

## 调用链

```text
研究范围或种子论文
→ cvpr-paper-analysis
→ cvpr-academic-search
→ 用户材料初步核验（有则执行，无则明确跳过）
→ 至少 5 个候选 IDEA 证据卡
→ cvpr-someagents 多角色审查
→ 修订与事实/引文一致性复核
→ cvpr-humanizer 第一人称表达
→ 再次核对事实和引用
→ 最多 5 轮用户讨论
→ 最终 IDEA 与初步验收目标
```

各子 Skill 必须按各自完整契约执行，不得只借用名称或根据记忆模拟。

## 强制流程

### 1. 凝练种子问题

用户可给研究范围、一个问题或一篇/多篇种子论文。论文材料调用 `cvpr-paper-analysis` 做全文分析，提取共性问题、矛盾、失败机制、边界条件和待验证假设。范围型输入先形成检索概念和初始问题清单。

### 2. 补充至少 10 篇新文献

调用 `cvpr-academic-search`。种子论文不计入新增数量；新增论文必须通过身份、时效性、相关性和证据定位核验。重新判断每个初始问题是已解决、部分解决、条件性解决、被重新定义、仍未解决，还是被最新证据进一步凸显。

### 3. 初步核验用户材料

用户提供数据、代码、日志、实验结果、标注或项目内容时，检查问题是否在用户情境中实际存在，并记录数据质量、实现条件和证据限制。用户没有材料时明确记为“按流程跳过”，不得生成替代数据或把文献证据冒充用户侧证据。

### 4. 形成至少 5 个候选 IDEA

每个候选必须按证据卡填写。正式候选至少需要两篇独立论文明确陈述或实验展示对应问题，其中至少一篇属于当前检索窗口内的近期工作，且至少一个证据可以定位到页码、章节、表格、图、公式或失败案例。

同时检查反证、已有解决方案、边界、创新性风险、可行性和证伪实验。少于 5 个候选通过证据门槛时，返回检索或问题重构，不降低标准，也不向用户呈报未达标候选。

### 5. 呈报前强制多 Agent 审查

调用通用 `cvpr-someagents` 的模式 B。所有 Agent 接收同一版本的证据包，各自按角色审查来源真实性与时效性、问题证据、相关工作与新颖性、方法与实验可证伪性、资源可行性和审稿风险。

`cvpr-someagents` 本身仍是可在任何阶段调用的通用原子 Skill；这里的强制性只属于本流程。未完成审查或重大异议未处置时，不得呈报候选 IDEA。

### 6. 人类化与一致性回查

候选内容通过审查后，可调用 `cvpr-humanizer` 形成自然的“我”或“我们”第一人称表达。随后必须再次核对数字、引文、证据强度、观点归属和候选结论；语言处理不得改变科研事实。

### 7. 最多 5 轮讨论并收敛

第一轮呈报至少 5 个合格候选；后续每轮围绕用户选择、质疑、约束和补证推进。整个启动阶段最多 5 轮用户讨论。

最终输出一个得到用户确认的 IDEA，包含研究问题、核心假设、预期贡献、成立条件、适用边界、关键风险、反证条件和初步验收目标。五轮后仍无法收敛时，状态记为 `needs-reframing`，总结分歧和缺失证据，不自动替用户选择。

IDEA 得到确认后，将 `$cvpr-goal` 作为下一原子任务，由它调查并固化领域匹配的验证载体、基线、判据和最终核验目标。`cvpr-start` 中的初步验收目标不能直接替代正式 `goal.yaml`。

## `.cvpr` 状态写入

如果项目已由 `cvpr-init` 建立 `.cvpr/`，以 [研究启动模板](assets/研究启动模板/start.yaml) 维护 `.cvpr/start.yaml`，记录检索截止日、材料版本、全部候选 IDEA、审查意见、用户决策和偏离项。未选候选不得因最终 IDEA 已确认而删除；后续 `cvpr-result` 触发 IDEA 循环时，需要用 `.cvpr/start.yaml` 中的历史候选证据卡与新的失败结果重新检查。

最终 IDEA 只有在用户确认后才能进入 `accepted`；验收目标仍是“初步目标”，不能伪装成已完成结果。写入后运行：

```bash
python3 <cvpr-start-Skill目录>/scripts/validate_start_manifest.py \
  <项目根目录>/.cvpr/start.yaml
```

校验未通过时保持草案、重构或阻塞状态，不得交给 `cvpr-goal`。

没有 `.cvpr/` 时可以完成讨论，但不得在未经用户确认的目录创建长期状态。需要长期管理时先调用 `cvpr-init`。

## 停止条件

全文不可得、新增合格论文不足 10 篇、候选不足 5 个、证据不能定位、审查未完成或五轮内未收敛时，明确停在相应状态并说明缺口。禁止自动减少文献数量、降低候选证据门槛或跳过审查。长期项目只有 `.cvpr/start.yaml` 通过校验后，才算具备可恢复和可循环使用的研究启动证据。
