# 单次检查与正式核验边界

## 三层验证

### 1. 单次检查

面向一个原子任务或局部修改，回答“本次改动是否按预期工作”。可以使用小规模样例、合成输入或确定性夹具，典型内容包括：

- 接口与输出结构；
- 张量形状、类型和设备；
- 数据变换和标签对齐；
- 数值不变量；
- 局部前向、反向或梯度行为；
- 修复问题的回归检查；
- evaluator 的解析和聚合逻辑。

单次检查代码统一放入 `cvpr_workspace/checks/`，其运行记录标为 `development_check`。

### 2. 阶段验收

回答“阶段承诺的研究能力或证据是否形成”。它可以组合多个任务结果、实验和检查，但必须逐条对应 Plan 的 `stage_validation.acceptance_rules`。

研究开发阶段可以把必要单次检查作为部分证据。研究证据阶段还需要实际实验对象、对照、结果和分析。

### 3. Goal 正式核验

回答“最终研究目标是否达到”。只能使用 Goal 确认的：

- 评测协议及版本；
- 数据划分、benchmark、仿真、物理对象或人类评价对象；
- 运行条件；
- 指标或判断方法；
- 目标规则与组合逻辑；
- 必需证据产物。

正式核验代码或包装放入 `cvpr_workspace/goal_evaluation/`，运行记录标为 `goal_verification`。

## 不可替代关系

以下内容不能代替 Goal 正式核验：

- 导入成功；
- 训练或服务能启动；
- 单个 batch 或少量样例通过；
- 输出形状正确；
- 合成数据结果；
- 训练集表现；
- 未锁定条件的快速实验；
- README 或论文报告的数值；
- 退出码为零。

即使开发检查使用了真实样例，只要没有按 Goal 的完整协议执行，也不能成为最终验收结果。

## 正式核验保护

执行前比较 Goal、Plan、入口清单和实际配置。任何下列变化都视为偏离：

- 更换数据集、划分或场景；
- 改变预处理、后处理或标签规则；
- 改变指标实现、阈值或聚合；
- 选择性排除失败样本或运行；
- 只保留最佳运行；
- 改变 baseline 条件；
- 用代理指标替代必需判据。

偏离存在时停止形成通过结论，记录影响并请求用户裁决。

## 结果不满足目标

如实保存完整结果与失败证据，将判据写为 `not_met`。证据不足且没有已确认失败判据时写为 `indeterminate`。每个判据保存 `reason`、Run 和证据；`passed` 与 `not_met` 必须引用成功完成的正式核验 Run，`indeterminate` 必须定位缺失或冲突证据。

允许后续基于证据修订计划、Goal 或 IDEA，但修订必须经过对应上游 Skill 和用户确认。DO 判定完成后交给 `cvpr-result` 二次复核。

禁止删除负结果、调整阈值、缩小对象或修改统计规则来使现有运行“通过”。
