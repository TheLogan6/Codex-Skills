# 恢复、偏离与回退规范

## 恢复原则

恢复执行时以真实文件、进程、作业系统、代码版本和产物为准，状态摘要只作为定位线索。

依次核对：

1. 活动 Plan 和阶段是否仍为当前正式版本；
2. 当前任务最后一条事件；
3. 对应 Run 的最后一条事件；
4. 代码、配置、输入和环境是否变化；
5. 输出是否完整且未被覆盖；
6. 验收是否已经实际执行。

无法确认完成的运行写为 `interrupted` 或 `indeterminate`，不能推断为成功。

## 偏离记录

发现以下情况时追加 `deviations.jsonl`，并在 `state.yaml.active_deviations` 登记：

- 代码版本或修改范围偏离；
- 数据、划分、场景或实验对象偏离；
- 环境、资源或依赖偏离；
- 评测实现、条件、指标或统计偏离；
- 阶段顺序、依赖或产物偏离；
- 实际结果与预期机制明显冲突；
- 证据缺失、损坏或无法追溯。

偏离记录至少包含 ID、时间、所属阶段和任务、观察事实、证据、影响、严重性、状态及需要的决策。

## 回退层级

### 留在 `cvpr-do`

适用于不改变阶段目的、顺序、Goal 或 IDEA 的局部实现问题，例如接口适配、明确范围内的 bug、检查失败和可定位运行错误。

### 返回 `cvpr-plan`

适用于需要改变阶段边界、顺序、依赖、阶段产物或阶段验收路径，但 Goal 与开发基础仍不变的情况。先停止受影响阶段，与用户讨论并形成新 Plan 版本。

### 返回 `cvpr-goal`

适用于需要改变代码库或版本、研究对象、评测协议、数据对象、必需判据、目标值或验收逻辑的情况。不得由执行层直接改写。

### 返回 `cvpr-start`

适用于新证据实质性否定问题成立、IDEA 核心机制、已有解决状态或研究价值，需要重新形成研究 IDEA 的情况。

## 禁止自动处理

未经用户确认不得：

- 降低目标值；
- 缩小正式评测对象；
- 更换为更容易通过的数据或指标；
- 跳过失败阶段；
- 删除负结果；
- 用开发检查代替真实核验；
- 自动选择另一代码库、模型或方法；
- 把阻断记为已解决后继续。

## 恢复运行

恢复长运行时优先使用登记入口和明确恢复点。确认输出目录不会覆盖原证据，并创建新的 Run 事件。

如果原入口或配置已经改变，旧运行不能与新运行视为同一条件；应新建运行并在分析中区分。
