# 执行工作区契约

## 目录

项目根目录使用：

```text
cvpr_workspace/
├── checks/
├── entrypoints/
├── goal_evaluation/
├── configs/
├── analysis/
└── 入口清单.yaml
```

只创建实际需要的子目录和文件。核心研究实现仍位于真实项目结构。

## 清单根字段

`入口清单.yaml` 使用 JSON 表达的 YAML 1.2 子集：

```text
schema_version
manifest_id
status
project_root
workspace_root
goal_ref
plan_ref
research_profile
directory_contract
entries
updated_at
```

`status` 允许：

- `proposed`：尚未开始执行，可以没有入口；
- `active`：已进入执行，所有登记入口必须可定位；
- `superseded`：由后续清单取代。

## 研究类型

`research_profile.kind` 允许：

- `undetermined`
- `model`
- `non_model`
- `mixed`

正式执行不能为 `undetermined`。`model` 和 `mixed` 必须在 `required_entry_roles` 中包含 `training`、`validation` 和 `testing`，并在清单中各有至少一个活动入口。

## 入口字段

每项入口至少包含：

```text
id
role
scope
stage_refs
task_refs
purpose
code_path
config_paths
working_directory
manual_command
runtime_parameters
input_refs
output_refs
goal_protocol_refs
goal_criterion_refs
result_logic_refs
status
```

`role` 允许：

- `training`
- `validation`
- `testing`
- `stage_check`
- `goal_evaluation`
- `analysis`
- `data_preparation`
- `simulation`
- `human_evaluation`
- `physical_experiment`
- `other`

`scope` 允许：

- `development_check`
- `research_execution`
- `goal_verification`
- `evidence_analysis`

## 路径约束

- 清单中的项目文件路径使用项目根目录相对路径；
- 禁止 `..` 穿越项目根目录；
- `stage_check` 必须位于 `cvpr_workspace/checks/`；
- 新增的 `goal_evaluation` 必须位于 `cvpr_workspace/goal_evaluation/`；
- 新增的 `analysis` 必须位于 `cvpr_workspace/analysis/`；
- 包装入口位于 `cvpr_workspace/entrypoints/`；
- 项目原有训练、验证和测试入口允许位于原目录，但必须登记。

## 手动命令

`manual_command` 使用字符串数组，不保存 shell 拼接命令。命令必须直接调用登记的代码入口，禁止：

- `python -c`
- `bash -c` 或 `sh -c`
- heredoc
- 只存在于环境变量展开中的关键配置

`runtime_parameters` 逐项说明允许用户在运行时选择的参数。结果相关默认值和方法逻辑应在登记的代码或配置中。

## Goal 绑定

`scope` 为 `goal_verification` 时：

- `goal_protocol_refs` 不得为空；
- `goal_criterion_refs` 不得为空；
- 引用必须存在于 `goal.yaml`；
- 入口角色应为 `goal_evaluation`、`validation`、`testing`、`simulation`、`human_evaluation`、`physical_experiment` 或实际适用角色；
- 运行记录必须保存正式结果证据。

开发检查不得引用自己为 Goal 通过证据。
