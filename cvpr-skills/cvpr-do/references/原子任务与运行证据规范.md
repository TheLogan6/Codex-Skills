# 原子任务与运行证据规范

## 追加式任务记录

`tasks.jsonl` 使用事件化快照，既保留历史又能表达状态变化。新记录采用：

```json
{
  "id": "TASK-001-E001",
  "task_id": "TASK-001",
  "revision": 1,
  "previous_record_id": null,
  "event": "created",
  "created_at": "2026-07-28T10:00:00+08:00",
  "phase": "method-and-engineering",
  "stage_id": "STAGE-001",
  "status": "proposed",
  "objective": "实现并核对已确认的方法模块",
  "inputs": [".cvpr/plan.yaml"],
  "boundaries": ["不改变 Goal 评测协议"],
  "deliverables": ["src/方法模块.py"],
  "acceptance_criteria": ["目标调用链使用新模块", "任务级检查通过"],
  "evidence_refs": [],
  "suggested_capability": "cvpr-do"
}
```

- `id` 是账本记录 ID，全文件唯一；
- `task_id` 是原子任务稳定 ID；
- `revision` 从 1 递增；
- 后续记录通过 `previous_record_id` 指向该任务上一条记录；
- 每条记录保存完整任务快照，不依赖覆写旧行。

旧版只有 `id` 的记录按“记录 ID 与任务 ID 相同、修订 1”解释。为旧任务追加状态时使用新格式。

## 任务事件

建议事件：

- `created`
- `started`
- `executed`
- `accepted`
- `blocked`
- `rejected`
- `superseded`

事件名描述本次变化，`status` 描述变化后的状态。`accepted` 记录必须有非空 `evidence_refs`。

## 运行记录

`runs.jsonl` 中每行是唯一运行事件，使用不同的记录 `id` 和稳定 `run_id`：

```json
{
  "id": "RUN-001-E001",
  "run_id": "RUN-001",
  "event": "completed",
  "created_at": "2026-07-28T11:00:00+08:00",
  "stage_id": "STAGE-001",
  "task_id": "TASK-001",
  "entry_id": "ENTRY-001",
  "kind": "development_check",
  "status": "succeeded",
  "code_version": {
    "commit": "不可变提交或基准版本",
    "working_tree_state": "clean-or-dirty",
    "diff_ref": "差异或补丁定位"
  },
  "config_refs": ["cvpr_workspace/configs/实验.yaml"],
  "command": ["python3", "cvpr_workspace/checks/检查方法.py"],
  "environment_refs": ["环境锁定文件或容器标识"],
  "input_refs": ["输入定位"],
  "output_refs": ["输出定位"],
  "protocol_refs": [],
  "criterion_refs": [],
  "result_summary": "检查结果摘要",
  "evidence_refs": ["日志或结果文件"],
  "deviation_refs": []
}
```

运行事件建议使用：

- `started`
- `progress`
- `completed`
- `failed`
- `interrupted`

每个事件拥有唯一 `id`。失败或终止事件同样保留其日志和输出。

## 结果记录

Goal 正式运行应在结果产物中保存结构化判据值或判断，至少包含：

- 指标或判断名称；
- 值、单位和统计范围；
- 运行与样本数量；
- 条件和协议版本；
- baseline 或对照；
- 不确定性、方差或适用的统计量；
- 原始证据定位。

指标形式由 Goal 决定，不在执行 Skill 中预设。

## 证据引用

证据引用应稳定定位到以下一种或多种对象：

- 代码文件与版本；
- 配置文件；
- 原始日志；
- 结构化结果；
- 模型或系统产物；
- 数据清单或哈希；
- 外部评测返回；
- 人类评价或实验记录；
- 统计分析产物；
- 决策或偏离记录。

只写“见输出”“已运行”“效果更好”不构成有效证据。
