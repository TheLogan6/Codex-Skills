# 阶段执行流程

## 1. 预检

完整读取 Goal、Plan、当前状态和账本，确认：

- Goal 与 Plan 均为用户确认的正式版本；
- 开发代码库、不可变版本和目标系统一致；
- 当前工作区中的既有改动归属明确；
- 当前阶段依赖与进入条件满足；
- 数据、环境、算力和外部资源仍符合协议；
- 没有阻断当前阶段的开放偏离。

预检只能根据真实材料通过。状态文件声称“已完成”但找不到证据时，应恢复为待核验状态并讨论。

## 2. 激活阶段

在 `state.yaml` 登记活动 Plan 和当前阶段，为 Plan 中每个阶段建立运行时状态快照。正式 `plan.yaml` 是经过确认的规划契约，不用作高频状态文件。

一个阶段的依赖只有在依赖阶段为 `accepted` 时才算满足。`executed` 不满足依赖。

## 3. 创建原子任务

围绕当前阶段的完整目的拆分任务。一个任务应能在不改变阶段设计的前提下单独执行和判断，例如：

- 实现一个清晰的方法能力；
- 准备一种确定的数据或实验输入；
- 建立并运行一种局部检查；
- 完成一组同条件实验；
- 执行一个正式评测协议；
- 统计并核对一组结果。

“完成整个模型”“优化效果”“验证所有目标”仍然是阶段级描述，不是原子任务。

## 4. 实施与检查

修改前检查真实调用链、配置继承和既有约定。修改后运行与本次风险直接相关的单次检查，并保存检查代码。

单次检查失败时停留在当前任务，定位原因并记录。不要跳过检查进入正式实验，也不要自动换用更简单的实现。

## 5. 稳定执行

先建立或登记稳定入口与配置，再运行会形成研究证据的工作。每次运行使用独立 Run ID 和独立输出位置；重复或恢复运行也建立新记录。

长运行启动后保存：

- 入口与配置；
- 代码版本及未提交差异定位；
- 环境定位；
- 输入与输出；
- 进程、作业或远程运行标识；
- 恢复方式。

## 6. 任务验收

运行成功只表示产生结果。按任务自身验收标准核对产物完整性、数值或行为、异常和证据位置，再决定任务状态。

任务失败仍可形成有价值的负结果或诊断证据，但不能因此标记为 `accepted`，除非任务目标本身就是完成该诊断且验收标准已经满足。

## 7. 阶段验收

所有任务完成后重新读取 Plan 中该阶段的验收规则，避免用执行过程中临时形成的便利标准替换原标准。

阶段验收记录至少包含：

- 阶段 ID 和 Plan 版本；
- 任务及 Run 引用；
- 每条验收规则的结论；
- 产物和原始证据；
- 已知限制与偏离；
- 阶段状态。

## 8. 推进或回退

阶段通过后清除当前任务，更新最后验收阶段，再选择下一可执行阶段。发现计划、Goal 或 IDEA 层问题时按回退规范处理，不在执行层偷偷重写上游契约。
