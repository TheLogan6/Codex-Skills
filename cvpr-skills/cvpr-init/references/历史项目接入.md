# 历史项目接入

## 目标

把已有代码、实验、论文或研究记录接入 `.cvpr/`，同时保留证据边界，不伪造过去的任务轨迹。

## 反向盘点

只读检查：

- 版本控制状态、主要模块、配置和测试；
- 数据说明、划分、预处理和许可证记录；
- 实验命令、日志、指标、模型文件和时间信息；
- 论文草稿、图表、表格、引用和研究笔记；
- 能够关联的提交、运行 ID、文件路径和外部记录。

将发现分为：

- `verified`：有稳定证据位置；
- `reported`：用户说明但当前无法核验；
- `unknown`：材料不足；
- `conflicting`：来源之间冲突。

## 状态重建原则

- 不补造过去的原子任务、运行时间或决策过程。
- 只有满足明确完成标准且有证据定位的事项可以登记为 `accepted`。
- 已运行但未验收的实验或工作登记为 `executed`。
- 用户口述的重要历史信息写入 `history_reconstruction.reported_items`，不写入已确认结论。
- 冲突信息写入 `history_reconstruction.conflicts` 并作为开放问题。
- 用一条“历史项目接入”决策说明本次状态重建的证据范围。
- 发现历史候选 IDEA 时可以建立 `start.yaml` 草案，但只有文献、候选审查和用户确认均可定位且通过 `cvpr-start` 校验器时才能恢复为 `accepted`；否则保持 `proposed`、`in_progress` 或 `blocked`。

## 草案输出

先向用户展示：

1. 识别到的研究目标与当前阶段；
2. 可核验的历史成果；
3. 仅被报告但未核验的事项；
4. 未知项和冲突；
5. 可能的偏离；
6. 推荐的一个主原子任务；
7. 准备写入 `.cvpr/` 的状态重建摘要。

用户确认前不得创建 `.cvpr/`。
