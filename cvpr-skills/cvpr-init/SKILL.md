# CVPR Init

将 `cvpr-skill` 视为覆盖整个 AI/ML/DL 领域的科研流品牌，不把项目限制为计算机视觉或 CVPR 投稿。维护长期项目状态，同时把具体工作收敛为可独立验收的原子任务。

## 核心边界

- 只做项目识别、只读盘点、状态草案、进度讨论和下一任务定义。
- 不直接检索或精读论文，不修改研究代码，不运行实验，不统计正式结果，不撰写论文。
- 可以使用 `find`、`rg`、Git 只读命令和文件读取检查用户指定范围内的真实材料。
- 首次运行先在对话中给出初始化或接入草案；获得用户确认后才创建或更新项目内 `.cvpr/`。
- 不把文件存在、代码可运行或文字声称当作研究完成证据。无法核验的历史信息记为未知。
- 不采用自动替代、静默缩减目标或任何形式的优雅降低。结构无效或关键信息不足时，停止相应写入并明确报告。
- 每次只推荐一个主原子任务；仅列出使主任务能够开始的少量依赖。

## 运行流程

### 1. 确定项目根目录

优先采用用户明确给出的目录。未给出时，从当前工作区识别候选项目根目录；存在多个合理候选时先讨论，不跨项目聚合状态。

检查 `<项目根目录>/.cvpr/`：

- 不存在且几乎没有既有材料：采用“新项目初始化”。
- 存在：采用“已有项目回读”。
- 不存在但已有代码、实验结果、论文或研究记录：采用“历史项目接入”。

完整读取与当前模式相关的规则：

- 新项目初始化：读取 [新项目初始化.md](references/新项目初始化.md)。
- 已有项目回读：读取 [已有项目回读.md](references/已有项目回读.md)。
- 历史项目接入：读取 [历史项目接入.md](references/历史项目接入.md)。
- 任何将创建或修改 `.cvpr/` 的情况：读取 [状态契约.md](references/状态契约.md)。

### 2. 只读盘点真实材料

限定在用户授权的项目范围内，优先检查：

- 项目说明、研究笔记、计划、数据说明；
- 代码结构、配置、测试、依赖和 Git 状态；
- 实验配置、日志、指标、模型产物和运行记录；
- 论文草稿、图表、表格和引用库；
- 已有 `.cvpr/` 状态文件。

记录“观察到了什么”和“仍不能确认什么”。不要在初始化阶段对方法新颖性、实验有效性或论文结论作超出证据的判断。

### 3. 形成草案并讨论

在任何写入前，输出：

- 进入模式与项目根目录；
- 当前研究阶段及判断依据；
- 已确认事实；
- 未知或待核验信息；
- 开放问题、阻断项与已观察到的偏离；
- 建议的一个主原子任务及其必要依赖；
- 准备创建或更新的 `.cvpr/` 内容摘要。

新项目允许研究方向、问题或 IDEA 为暂定状态，不要求初始化时冻结完整课题。只询问会改变当前定位或下一任务的关键问题。

### 4. 等待用户确认

用户未确认时：

- 不创建 `.cvpr/`；
- 不改写已有 `.cvpr/`；
- 不进入下游研究工作。

若用户修订草案，先更新对话中的草案，再次确认。确认只覆盖明确展示的初始化或更新范围。

### 5. 创建或更新状态

用户确认后：

- 新建时以 `assets/项目状态模板/.cvpr/` 为结构基准；
- 使用项目真实信息替换模板值；
- 历史项目只能把有明确证据的事项登记为 `accepted`；
- 为初始化决策写入 `decisions.jsonl`；
- 若已经确定下一任务，将其按状态契约的事件化快照写入 `tasks.jsonl`，首条记录状态设为 `proposed`，不能提前写成已完成；
- 更新后运行：

```bash
python3 scripts/validate_cvpr_state.py <项目根目录>
```

基础状态通过后，按实际存在的文件继续执行责任契约校验：

1. `start.yaml`：调用 `cvpr-start/scripts/validate_start_manifest.py`；
2. `goal.yaml`：调用 `cvpr-goal/scripts/validate_goal_contract.py`，并传入 `--start-file`；
3. `plan.yaml`：调用 `cvpr-plan/scripts/validate_plan_contract.py`，并传入 `--goal-file`；
4. `result.yaml`：调用 `cvpr-result/scripts/validate_result_review.py`，并传入 `--state-file` 和项目根目录；
5. `paper.yaml`：调用 `cvpr-paper/scripts/validate_paper_state.py` 核验论文快照、产物状态和失效传播。

基础状态校验不能替代可选契约校验。存在下游契约而缺少其上游权威文件时，报告链路断点并停止对应阶段恢复；不能只从 `project.yaml.working_idea`、进度摘要或论文文字推断权威状态。

校验失败时停止后续路由，列出错误，不改用简化结构。

## 进度讨论格式

按以下顺序汇报：

1. 当前阶段；
2. 最近完成并验收的原子任务；
3. 已确认结论及其证据位置；
4. 开放问题；
5. 阻断项；
6. 已登记或新发现的偏离；
7. 推荐的一个主原子任务；
8. 必要依赖与完成标准；
9. 需要用户确认的状态变更。

“最近完成”只接受 `accepted` 任务。`executed` 表示已执行但尚未通过验收，不能与 `accepted` 混用。

## 原子任务定义

下一任务至少包含：

- 唯一任务 ID；
- 唯一账本记录 ID、任务修订和上一记录引用；
- 单一、可验证的目标；
- 输入材料与证据位置；
- 所属长期阶段；
- 操作边界；
- 预期产物；
- 完成标准；
- 当前状态；
- 建议调用的后续技能或执行能力。

初始化只定义任务，不执行任务。

## 停止条件

出现以下任一情况时停止相应写入：

- 项目根目录不明确；
- 已有 `.cvpr/` 缺少必需文件、解析失败或交叉引用无效；
- 用户尚未确认草案；
- 历史完成状态缺乏可定位证据；
- 多份状态互相冲突且无法从真实材料裁决；
- 下一任务目标、边界或完成标准仍无法明确。

报告阻断原因、受影响的状态文件和需要用户决定的事项。
