# 多 Agent 计划审查协议

## 编排方式

调用通用 `cvpr-someagents` 模式 B。至少两个独立 Agent 接收同一版本证据包，每个 Agent 使用不同且互补的审查角色。

证据包包含：

- 已确认 IDEA；
- `goal.yaml`；
- 真实代码检查记录；
- 初步阶段计划；
- 用户边界和开放问题。

## 审查视角

按项目实际覆盖：

1. 代码一致性：阶段是否符合真实结构、依赖和改动范围；
2. 科研路径：计划是否能够实现并检验 IDEA；
3. Goal 覆盖：必需判据是否都有证据和真实验证阶段；
4. 实验有效性：对照、数据、协议和结论是否可能失真；
5. 验证真实性：是否把开发检查冒充正式评测；
6. 工程适度性：是否遗漏必要可执行性，或引入与研究无关的工业工程。

不要求每个视角单独派一个 Agent，但最终不能遗漏与项目有关的视角。

## 输出结构

```yaml
agent_id: ""
role: ""
verdict: pass | revise | reject
findings: []
blocking_issues: []
evidence_refs: []
```

协调者汇总：

- 重复发现；
- 角色间分歧；
- 阻断问题；
- 已完成修订；
- 仍需用户决定的问题；
- 审查证据位置。

## 通过条件

- 至少两个独立 Agent 已完成；
- 输入计划版本一致；
- 每个结论有理由或证据；
- 所有阻断问题已解决或明确交给用户讨论；
- 少数派实质风险被保留；
- 审查结果写入计划草案。

在用户呈报前完成审查。`cvpr-someagents` 本身仍是通用原子 Skill，这里的强制性只属于 `cvpr-plan`。
