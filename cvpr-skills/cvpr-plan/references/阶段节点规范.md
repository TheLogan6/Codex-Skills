# 阶段节点规范

## 阶段粒度

阶段是具有完整科研目的的一段工作，不是原子步骤。

不合格节点：

- 修改一个文件；
- 执行一条命令；
- 检查一次导入；
- 跑一个样例；
- 修复一个局部报错。

这些可以成为阶段内部的原子任务或开发检查。

合格节点应说明：

- 该阶段要形成什么研究能力或证据；
- 它依赖哪些前置阶段；
- 涉及哪些真实代码、数据、环境或实验对象；
- 产出什么可定位结果；
- 怎样判断阶段完成。

## 必需字段

```yaml
id: STAGE-001
order: 1
name: ""
objective: ""
goal_criterion_refs: []
dependencies: []
entry_conditions: []
code_context: []
stage_scope: []
excluded_scope: []
expected_outputs: []
stage_validation:
  kind: research_development
  description: ""
  protocol_refs: []
  evaluation_objects: []
  acceptance_criteria_refs: []
  acceptance_rules: []
  evidence_artifacts: []
user_decision_points: []
blocking_conditions: []
status: proposed
```

## 顺序与依赖

`order` 表示主要推进顺序，`dependencies` 表示真实前置关系。依赖必须指向更早阶段，不允许循环。

并行不是计划默认行为。确有互不依赖的阶段时可以拥有相同前置阶段，但是否并行由后续执行编排根据资源和修改冲突决定。

## 验收种类

- `research_development`：形成研究实现或能力；
- `research_evidence`：形成实验、数据或机制证据；
- `goal_verification`：执行 Goal 锁定的真实核验；
- `evidence_audit`：统计、核对和审计最终证据。

所有阶段都需要可检查的验收，但只有 `goal_verification` 能直接承担最终 Goal 判据。

## 状态

阶段使用统一状态：

- `proposed`
- `running`
- `executed`
- `accepted`
- `blocked`
- `rejected`
- `superseded`

计划首次确认时，各阶段通常仍为 `proposed`。该字段记录计划获确认时的初始状态；`cvpr-do` 不频繁改写正式 `plan.yaml`，而是根据实际证据更新 `.cvpr/state.yaml.stage_statuses`。计划修订仍通过新的 Plan 版本完成。

## 禁止时间字段

计划只表达顺序、依赖、验收和阻断，不记录工期、预计时长、排期、截止日期、Sprint 或日历承诺。
