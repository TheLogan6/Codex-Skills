# 审计报告与路由契约

## 根字段

机器可读审计记录采用 JSON 表达的 YAML 1.2 子集：

```text
schema_version
audit_id
version
status
created_at
updated_at
snapshot
scope
ledger_refs
coverage
checks
findings
summary
supersedes
```

## 检查与问题

每个 `check` 必须记录检查类别、状态、位置、证据和说明。状态只能是 `pass`、`fail` 或 `not_assessable`。

每个 `finding` 必须包含：

- 唯一 `finding_id`；
- `blocker`、`major` 或 `minor`；
- 检查类别和简明标题；
- 事实描述与影响；
- 至少一个精确位置；
- 至少一个证据引用；
- 开放状态；
- 唯一责任 Skill 和建议路由。

审计报告不得携带正文补丁或改写后的段落。

## 责任路由

| 问题 | 责任 Skill | 建议路由 |
|---|---|---|
| 论证、章节、Claim 表达 | `cvpr-writing` | `return-to-writing` |
| 引用支持或 BibTeX | `cvpr-citation` | `return-to-citation` |
| 统计数字和聚合 | `cvpr-statistics` | `return-to-statistics` |
| 图形、图注和源数据 | `cvpr-figure` | `return-to-figure` |
| 代码、数据、配置与声明 | `cvpr-reproducibility` | `return-to-reproducibility` |
| 模板、匿名和版面 | `cvpr-latex` | `return-to-latex` |
| 缺少新实验或 Run 证据 | `cvpr-do` | `return-to-do` |
| 冻结 Result 与稿件依赖错误 | `cvpr-result` | `return-to-result` |

`request-materials` 只用于缺少输入导致的 `blocked`。修复完成后必须重新冻结并重新审计。

## 状态判定

- `ready`：范围必须为 `full`；所有类别已评估；所有检查均为 `pass`；不存在开放 blocker/major。
- `needs_revision`：审计已完成，至少有一个开放问题或失败检查。
- `blocked`：存在关键缺失材料或不可评估的必查类别。
- `proposed`、`in_progress`、`superseded` 不表示审计结论。

`ready` 只表示确定性审计通过，不表示论文科学质量通过，也不表示任何 venue 会录用。
