# CVPR Paper Audit

## 定位

把本 Skill 作为可独立调用的确定性审计能力。名称中的 CVPR 表示 `cvpr-skills` 品牌，不把检查规则写死为 CVPR 会议；目标 venue 只在用户已经指定且提供正式要求时参与检查。

只报告可复核的一致性、完整性和追溯问题。不得重写正文、重算实验、替换图表、修改引用、改变 Goal、覆盖 `cvpr-do` 判定或改写 `cvpr-result` 结论。科学贡献是否成立、是否足够新颖以及是否应录用属于 `cvpr-reviewer` 或真实审稿流程，不属于本 Skill。

## 必读规范

- 执行审计前读取 [审计流程与冻结快照.md](references/审计流程与冻结快照.md)。
- 建立检查项和严重性时读取 [全文一致性检查矩阵.md](references/全文一致性检查矩阵.md)。
- 生成问题清单、状态和路由时读取 [审计报告与路由契约.md](references/审计报告与路由契约.md)。

## 输入

优先读取当前项目中：

- 已冻结稿件、补充材料和附录；
- `.cvpr` 中已接受的 IDEA、Goal、Result 及论文账本；
- Claim—证据、数字、引用、术语与符号账本；
- 表格、图形和各自的源数据；
- 纳入论文的 Run、统计任务及其产物；
- 代码、数据、配置、模型和复现材料清单；
- 用户已指定 venue 的正式模板或政策证据。

独立调用时可以审计用户给出的局部材料，但必须把范围标为 `partial`，明确未提供内容，且不能给出全文 `ready`。

## 工作流

1. **冻结输入。** 建立唯一 `snapshot_id`、冻结时间、清单摘要和文件 SHA-256。审计期间不得静默替换文件；输入变化时结束本轮并创建新快照。
2. **确定范围。** 列出纳入稿件、证据账本、运行、统计、图表、复现材料和 venue 约束。缺少核心输入时保留缺口，不猜测。
3. **建立位置索引。** 对正文使用页码、行号、章节、公式号、表号或图号；对证据使用 Run、配置键、文件路径或数据单元格。每个问题至少有一个精确位置。
4. **执行检查矩阵。** 覆盖稿件完整性、Claim、数字、表格、图形、公式、引用、术语、Run、统计和复现材料。不能因为某类没有显性错误就省略其检查记录。
5. **登记问题。** 为每项问题记录严重性、事实描述、影响、位置、证据、责任 Skill 和建议路由。不要在审计过程中顺手修复。
6. **形成状态。** 按契约生成 `ready`、`needs_revision` 或 `blocked`，不得生成 accept/reject 或任何会议录用判断。
7. **固化与校验。** 以 [论文审计模板](assets/论文审计模板/paper-audit.yaml) 写入项目指定位置，并运行：

```bash
python <cvpr-paper-audit目录>/scripts/validate_paper_audit.py \
  <审计文件> \
  --project-root <项目根目录>
```

若当前 Python 不在 PATH，使用工作区已经提供的 Python 运行时；不得为通过检查而删字段或降低规则。

## 状态与路由

- `proposed`：模板或尚未执行的审计任务；
- `in_progress`：已冻结输入，检查尚未完成；
- `ready`：完整范围内所有必查类别均可评估，没有开放的 blocker/major，也没有失败或不可评估的必查项；
- `needs_revision`：审计完成，但存在应由原子 Skill 修复的问题；
- `blocked`：关键稿件或证据缺失，无法完成可靠审计；
- `superseded`：输入快照变化，由新审计取代。

常见责任 Skill 包括 `cvpr-writing`、`cvpr-citation`、`cvpr-statistics`、`cvpr-figure`、`cvpr-reproducibility`、`cvpr-latex`、`cvpr-do` 和 `cvpr-result`。路由只是问题归属建议，不能自动修改上游事实或自动执行回退。

## 完成标准

- 冻结快照和稿件范围可识别；
- 十一类必查内容都有明确结论；
- 所有问题均有精确位置、严重性、证据、影响和责任 Skill；
- 正文数字能够追溯到表格、统计产物和 Run；
- Claim、引用、图表、公式、术语和复现材料之间没有被静默跳过的矛盾；
- 审计没有修改稿件或科研结论；
- 输出契约通过确定性校验。
