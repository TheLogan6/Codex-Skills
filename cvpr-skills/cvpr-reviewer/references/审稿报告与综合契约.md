# 审稿报告与综合契约

## 根字段

审稿记录采用 JSON 表达的 YAML 1.2 子集：

```text
schema_version
review_id
version
status
created_at
updated_at
snapshot
scope
orchestration
axes
reviewer_reports
synthesis
supersedes
```

## 单份报告

每份报告包含：

- 审稿人编号、侧重点、独立性和输入 `snapshot_id`；
- 对全部适用轴的逐项评估；
- 有证据引用的 strengths；
- 结构化 findings；
- 不可评估内容、限制和总体科学状态。

finding 必须具有唯一 `finding_id` 和可跨报告聚合的 `finding_key`，并记录轴、严重性、事实说明、影响、稿件位置、证据、所需行动和开放状态。

总体科学状态只能使用：

- `ready_within_scope`
- `revision_required`
- `blocked_by_missing_evidence`

这些不是编辑决定。

## 综合规则

综合报告必须建立 `finding_registry`。每个条目列出：

- `finding_key`；
- 所有来源 `finding_id`；
- 所有提出该问题的审稿人；
- `consensus` 或 `minority`；
- 合并后的严重性、说明和处理状态。

三份报告中的每个 finding 必须且只能进入一个 registry 条目。仅一位审稿人提出的问题必须分类为 `minority` 并列入 `minority_finding_keys`；不能因未获多数支持而删除。

## 状态

- `reviewed`：完整稿件、三审完成、所有轴可评估且没有开放 blocker/major；
- `needs_revision`：三审完成，但存在开放 blocker/major 或 `weak` 评估；
- `blocked`：核心输入缺失，至少一个轴无法评估；
- `proposed`、`in_progress`、`superseded` 不表示科学结论。

综合状态不是 accept/reject，不预测录用。`reviewed` 后仍须由用户决定是否继续润色、排版或真实投稿。

## 禁止字段

记录中不得出现编辑决定、录用建议、录用概率、虚构身份、作者 rebuttal 或自动修改稿件的字段。发现这些内容时确定性校验必须失败。
