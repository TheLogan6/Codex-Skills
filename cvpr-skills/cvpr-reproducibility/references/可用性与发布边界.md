# 可用性与发布边界

## 事实先于措辞

先建立材料清单和核验记录，再写 Code/Data/Model Availability。每个声明句必须能够映射到材料 ID 或经过核验的外部断言。

下列内容一律不得从记忆补写：

- URL、DOI、accession、仓库名称或 reviewer link；
- 许可证名称、版本和再分发权；
- “已公开”“录用后公开”“可申请访问”等状态；
- 数据所有者、审批主体、申请条件和解禁日期。

## 可用状态

- `public`：无需额外授权即可通过已核验稳定入口访问。
- `private_reviewer`：仅审稿期匿名访问，不能描述为公开。
- `controlled`：有明确机构、委员会或仓库流程审核访问。
- `restricted`：因法律、伦理、商业或第三方条款不可直接提供。
- `local_only`：当前仅本地存在。
- `planned`：已计划但尚未完成；不能在成稿中使用过去时。
- `unknown`：事实未核验。

“可向作者合理索取”不是默认方案。若确有受限材料，应说明限制原因、持久负责主体、资格、审批或协议条件，并确认不泄露匿名身份。

## 匿名审稿

检查：

- 仓库组织名、用户名、提交作者、Issue、Release 和 URL 不暴露身份；
- PDF 元数据、文件路径、日志、模型卡、数据卡和脚本注释不暴露身份；
- acknowledgements、基金、机构算力名称与自引措辞符合目标规则；
- reviewer link 可访问但不具有编辑权，不暴露个人账号；
- 双盲版本与公开版本分别管理，不从公开包反向覆盖匿名包。

发现身份线索时报告位置和修复方向；未经用户确认不修改 Git 历史或公开仓库。

## 公开发布

逐项确认：

- 仓库或归档版本与冻结 Result 一致；
- 发布包含运行说明、环境、配置、数据或获取流程、预训练资产来源；
- 第三方资产允许再分发，不能把可下载等同于可再发布；
- 新代码、新模型和新数据的许可证由有权主体确认；
- 持久标识符真实解析，版本、tag 与校验信息一致；
- 不包含密钥、私有服务器地址、个人数据或受限数据。

公开、上传、改许可证和创建持久记录都是外部状态改变，必须获得用户明确授权。

## 声明输出

分别起草：

1. Code Availability；
2. Data Availability；
3. Model/Checkpoint Availability；
4. 必要时的受限访问说明；
5. 与 Supplementary 或匿名仓库的精确文件映射。

不能确认的字段保留机器可读 unresolved 项并在用户呈报中说明，不生成看似完整的占位 URL。
