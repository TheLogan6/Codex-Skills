# CVPR 复现材料

## 定位

作为可独立调用的原子能力，检查论文结论所依赖的研究材料是否可定位、可解释、可访问并具备明确发布状态。包名中的 CVPR 代表工作流品牌，不限定会议或研究方向。

不实现研究代码，不运行或补造实验，不替 `cvpr-do` 判定 Goal，不修改 `cvpr-result`，不替论文作者承诺尚未完成的公开发布。

## 必读规范

- 清点或审计材料时读取 [复现材料工作流.md](references/复现材料工作流.md)。
- 起草可用性声明、处理匿名或公开发布时读取 [可用性与发布边界.md](references/可用性与发布边界.md)。
- 创建或更新机器记录时读取 [复现契约.md](references/复现契约.md)。

## 输入门禁

正式论文复现产物必须读取：

- 已冻结且已接受的 `.cvpr/result.yaml` 及其 `snapshot_id`；
- 该快照引用的 Run、代码版本、配置、统计、图形和偏离记录；
- 项目实际文件与论文当前稿件；
- 用户已确认的目标 venue、track 和 submission stage；若暂未确定，只生成通用材料审计，不生成 venue 合规结论。

缺少冻结 Result 时，可以执行局部盘点，但状态只能是 `proposed` 或 `blocked`，不得宣称论文复现包完成。

## 工作模式

- `inventory`：建立完整材料目录与来源映射。
- `audit`：核对可定位性、完整性、访问条件、许可证与敏感性。
- `paper_statement`：生成 Code/Data/Model Availability 草稿及精确材料映射。
- `anonymous_release`：准备不泄露作者身份的审稿访问材料。
- `public_release`：准备公开仓库、持久标识符、许可证和版本化发布记录。

一个调用只选择当前需要的模式；需要多个模式时按 `inventory → audit → statement/release` 的依赖顺序执行。

## 工作流

### 1. 冻结输入范围

记录 `snapshot_id`、Result 文件、代码版本、数据版本和稿件版本。任何材料变化都必须生成新审计版本；不覆盖旧记录。

### 2. 分类清点

必须逐类覆盖代码、配置、环境、随机种子、数据、数据划分、模型、检查点、日志、统计源、图形源和第三方资产。某类不适用时记录理由，不能因未发现文件而静默跳过。

对每项保存稳定路径或外部标识、版本/校验信息、支持的 Claim 或 Run、访问状态、许可证状态、敏感性和证据。

### 3. 核对可复现链

从关键论文结论逆向追踪至运行、配置、代码、数据、环境和输出。标记：

- `complete`：证据闭环；
- `partial`：存在明确缺口；
- `not_applicable`：经说明不适用；
- `unknown`：尚未确认。

不得把本地存在等同于外部可访问，也不得把计划公开写成已经公开。

### 4. 核验声明事实

URL、DOI、accession、许可证名称、公开状态、访问条件和匿名链接必须逐项记录核验状态与证据。无法核验时保持 `unverified` 或 `conflicting`，并在声明中使用明确待定项，不能生成貌似真实的值。

### 5. 处理敏感和受限材料

识别个人信息、密钥、内部地址、商业数据、未公开身份线索和受许可证约束的材料。公开包与匿名审稿包分别建立允许内容清单；不复制或暴露密钥、凭证和受限原始数据。

### 6. 生成产物

在项目中建议写入：

```text
cvpr_workspace/result_package/reproducibility/
├── reproducibility.yaml
├── inventory/
├── statements/
├── anonymous/
└── release/
```

从 [复现任务模板](assets/复现任务模板/reproducibility.yaml) 建立记录，输出复现清单、缺口与风险、材料映射、可用性声明草稿和相应发布准备报告。

### 7. 校验与呈报

运行：

```bash
python3 <cvpr-reproducibility目录>/scripts/validate_reproducibility_manifest.py \
  <项目根目录>/cvpr_workspace/result_package/reproducibility/reproducibility.yaml \
  --project-root <项目根目录>
```

向用户分别呈报：已核验事实、未核验声明、阻断缺口、敏感材料、匿名审稿准备和公开发布准备。不得将风险折叠成单一“可复现”结论。

## 硬性边界

- 不伪造 URL、DOI、accession、许可证、版本、校验和、公开状态或访问流程。
- 不自动上传仓库、不公开材料、不变更许可证；这些外部状态改变需用户明确授权。
- 不把实验失败、缺少 Run 或证据冲突包装成复现性问题。
- 不修改 Goal、Plan、DO 判定或 Result 路由。
- 不为通过 venue 清单而声明并不存在的材料。
- 不输出密钥、令牌、个人联系方式或未经授权的受限内容。

## 完成标准

- 十二类材料都有明确评估；
- 关键 Claim 与 Run 的复现链可追溯或缺口已显式记录；
- 所有外部标识、许可证和公开状态均有核验状态；
- 声明内容与材料记录一致；
- 匿名包与公开包不存在敏感信息泄露；
- 正式完成状态绑定冻结 Result 快照；
- 机器契约校验通过，用户已看到缺口与风险。
