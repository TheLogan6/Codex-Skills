# 深度研读方法

## 来源优先级

按以下顺序使用材料：

1. 论文正式版本或作者提供的最新版全文；
2. 附录和补充材料；
3. 作者项目页、会议页面和勘误；
4. 官方代码仓库；
5. 二手材料只用于发现问题，不能代替原文证据。

记录论文版本。遇到 arXiv 与会议版本并存时，说明实际分析的是哪个版本。

## 第一遍：结构通读

通读摘要、引言、方法、实验和结论，先回答：

- 论文研究对象和任务是什么；
- 作者声称现有方法有什么缺陷；
- 核心贡献属于问题、方法、解释、数据还是工程改进；
- 哪些实验承担主要证明责任。

这一遍只建立全貌，不急于接受作者结论。

## 第二遍：因果重构

精读问题定义和方法，建立以下链条：

```text
观察到的缺陷
→ 对缺陷原因的判断
→ 新的假设或约束
→ 具体设计
→ 预期中间效果
→ 最终任务结果
```

对每项关键设计追问：

- 它解决的是哪个具体问题；
- 为什么是这种设计，而不是更直接的替代方案；
- 去掉它后理论上会发生什么；
- 它影响表达、优化、计算、数据效率还是泛化；
- 它依赖哪些隐含条件。

## 第三遍：证据审计

逐条检查作者主张：

- 是否有直接实验；
- 是否有消融或对照；
- 基线和训练配置是否公平；
- 增益是否稳定，还是只出现在少数设置；
- 效率是否包含真实速度、显存和硬件条件；
- 泛化结论是否覆盖足够任务、数据集和规模；
- 作者解释是否存在替代原因。

把结论分为“证据充分”“部分支持”“仍属推断”。不要把作者的机制解释直接当作已证实事实。

## 仓库旁证

完成论文方法理解后再查看仓库。优先核对与关键结论直接相关的模型实现、损失、配置和评测脚本。不要按目录逐文件汇报，也不要让工程细节挤占方法分析。
