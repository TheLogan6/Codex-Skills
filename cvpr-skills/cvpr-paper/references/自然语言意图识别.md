# 自然语言意图识别

## 原则

五种模式是路由器内部分类，不是用户命令。读取完整句子、对话上下文和当前论文状态后判断。不要要求用户复述为固定格式。

## 内部模式

| 模式 | 核心语义 | 是否执行 |
|---|---|---|
| `help` | 询问能力、方法或选择 | 否 |
| `status` | 查询进度、缺口或阻断 | 只读 |
| `task` | 请求一个主要产物 | 是 |
| `compose` | 请求多个有依赖的产物 | 是 |
| `full-draft` | 请求完整论文初稿 | 是 |

## 判断顺序

1. 先判断用户是在询问，还是要求采取动作。
2. 要求动作时判断主要交付物数量和依赖。
3. 涉及整篇稿件时判断是否为完整初稿。
4. 结合 `.cvpr/paper.yaml` 判断“继续”“完善”“还缺什么”的具体对象。
5. 仅在歧义会改变文件、论文主线、目标 venue 或研究结论时询问。

## 示例

| 用户原话 | 内部模式 | 路由 |
|---|---|---|
| `cvpr-paper 画消融图应该用什么？` | `help` | 回答 `cvpr-figure` |
| `cvpr-paper 帮我画消融图` | `task` | `cvpr-figure` |
| `cvpr-paper 论文现在还缺什么？` | `status` | 回读状态和账本 |
| `cvpr-paper 把表格、图和 Results 整理好` | `compose` | `cvpr-statistics → cvpr-figure → cvpr-writing` |
| `cvpr-paper 根据现有结果生成完整初稿` | `full-draft` | 完整初稿编排 |
| `cvpr-paper 这句话真实吗？` | `task` | 先查 Claim/证据；可能路由审计或引用 |

## 歧义

- “看看图”可能是审图或画图；若上下文无图，询问一次。
- “完善论文”必须从当前状态识别具体缺口；无法识别时列出最关键的一个分叉问题。
- “投稿 CVPR”不能直接解释为获得官方模板；模板与规则必须来自当前官方来源。

不要用“我判断为 task 模式，请确认”打断自然交互。可以简短说明“这需要先整理统计数据，再生成图形”，随后按授权范围执行。
