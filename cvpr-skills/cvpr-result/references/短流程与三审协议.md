# 短流程与三审协议

## 流程边界

`cvpr-result` 只执行：

```text
冻结 DO 结果
→ 三位独立审稿人
→ 协调整合
→ 路由
→ 通过后统计与绘图
→ 用户呈报
```

不在本阶段重新研究方法、重新规划实验或反复讨论 IDEA。

## 统一输入包

三位审稿人必须收到同一个不可变包：

- `snapshot_id`；
- Goal 和 Plan 版本；
- DO 最终判定及逐项判据结果；
- 代码版本和未提交差异定位；
- 入口、配置、环境、数据与 checkpoint；
- 纳入和排除的全部 Run；
- 原始结果、统计代码和汇总结果；
- baseline 和消融配置；
- 失败、终止、异常和偏离；
- 当前 IDEA 的研究主张与边界。

不能只给摘要而隐藏原始证据，也不能给不同审稿人不同的运行集合。

## 固定三角色

### `goal_and_protocol`

检查 DO 是否按 Goal 的真实对象、协议、条件、判据和组合逻辑作出结论。重点识别协议替换、数据划分变化、指标实现变化和判定越权。

### `experiment_and_ablation`

检查比较公平性、近期 baseline、实验设计、每项研究贡献的隔离证据、组件交互、运行选择和统计严谨性。

### `evidence_and_reproducibility`

检查原始结果到结论的追溯、失败与负结果、数据泄漏、测试集调参、代码配置环境定位、入口和重现条件。

## 独立性

- 使用 `cvpr-someagents` 模式 B；
- 三个 Agent 并行读取同一证据包；
- 角色提示只规定关注维度，不提供协调者结论；
- 全部提交前互不可见；
- 每人必须独立给出 `confirm`、`challenge` 或 `blocked`；
- 每项问题必须有证据定位和影响说明。

## 通过门槛

必须三人均为 `confirm`，且没有未解决阻断问题。多数票、平均分或“两票通过”不成立。

非阻断限制可以保留，但必须出现在用户呈报和后续论文边界中。

## 协调者

协调者负责：

- 核对三个输入快照是否相同；
- 合并重复发现；
- 保留独立和少数发现；
- 复查证据引用；
- 对分歧进行事实核验；
- 决定符合规则的下一路由。

协调者不得自行改变 DO Goal 判定。
