# 结果复核契约

## 根字段

`.cvpr/result.yaml` 使用 JSON 表达的 YAML 1.2 子集：

```text
schema_version
result_id
version
status
created_at
updated_at
do_assessment_ref
frozen_evidence
reviewer_reports
review_consensus
route
idea_feedback
statistics_artifacts
figure_artifacts
user_presentation
user_confirmation
supersedes
```

## DO 引用

`do_assessment_ref` 保存 Goal ID 和版本、`state.yaml` 定位、DO 判定、审计时间和证据引用。Result 不复制或重写 DO 的逐项结论。

正式复核必须与实际 `.cvpr/state.yaml` 联合校验，确保 Goal ID、版本、判定和审计时间一致。

## 冻结证据

`frozen_evidence` 至少包含：

- `snapshot_id`
- `frozen_at`
- `goal_ref`
- `plan_ref`
- `code_refs`
- `run_ids`
- `result_artifacts`
- `deviation_refs`

正式复核时不得为空。

## 三审报告

正式复核必须恰好三份报告，角色分别为：

- `goal_and_protocol`
- `experiment_and_ablation`
- `evidence_and_reproducibility`

每份报告包含：

```text
reviewer_id
role
independent
input_snapshot_id
status
verdict
findings
blocking_issues
limitations
evidence_refs
```

`independent` 必须为 `true`，`status` 必须为 `completed`，`verdict` 允许 `confirm`、`challenge`、`blocked`。

## 路由与产物

- `paper`：DO 必须为 `passed`、三审必须 `confirmed`、无阻断，统计与图形产物均非空，并把冻结 `snapshot_id` 交给 `cvpr-paper`；
- `restart-idea`：DO 必须为 `not_met` 或 `indeterminate`、三审必须 `confirmed`，`idea_feedback` 完整，并引用有效 `.cvpr/start.yaml` 的全部历史候选；
- 其他返回路由：三审为 `challenged` 或 `blocked`，并保存问题证据。

统计和图形产物分别登记原子 Skill 的任务契约、实际输出和证据引用；正式 `paper` 路由需要检查这些文件实际存在。

`restart-idea` 的 `idea_feedback` 除原 IDEA、失败判据、关键结果、审稿报告和历史候选外，还必须填写 `start_contract_ref`，指向上一轮有效 `.cvpr/start.yaml`。

## 用户确认

`accepted` 状态必须已经向用户呈报，并由用户确认下一路由。确认复核记录不等于确认 Goal 通过。
