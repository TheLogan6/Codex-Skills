# 核验目标形成流程

## 一、从 IDEA 到可观察结果

逐项重写已确认 IDEA：

```text
主张：我们认为 X 会改变 Y。
条件：该判断只在 Z 条件下成立。
可观察变化：如果主张成立，应观察到 O。
反证：如果出现 F，主张不成立或需要缩小。
核验对象：使用 E 才能直接观察 O。
```

一张核验契约可以包含多个主张，但每个必需验收判据只能服务于可明确说明的主张。没有主张关联的常用指标不要加入。

## 二、判断项目状态

### 已有项目

执行只读检查：

1. 定位真实项目根目录和仓库来源；
2. 核对当前分支、commit 或等效的不可变版本证据；
3. 识别准备修改的模型或系统及拟改动范围；
4. 搜索与主张相关的评测入口和配置；
5. 查找已有基线、运行记录和结果产物；
6. 判断当前实现是否对应论文、官方仓库或项目自定义协议；
7. 核对开发基础与候选核验协议的兼容性；
8. 将代码库、版本、改动对象、候选核验方案及风险呈报用户确认。

不要因为文件名包含 `val`、`eval` 或 `benchmark` 就直接认定为正式核验实现。

### 没有项目

留在 `cvpr-goal`，围绕已确认 IDEA 调查开发代码库：

1. 原论文及其正式补充材料指向的官方仓库；
2. 基础模型或系统的官方实现；
3. 作者持续维护的实现；
4. 其他确有必要比较的可信实现；
5. 每个候选的固定 commit/tag、许可、依赖和可执行条件；
6. IDEA 对应的模型、系统、模块或调用链；
7. 候选代码库与核验协议、数据、环境或实验设施的兼容性。

如果存在多个实现，比较权威性、与 IDEA 的直接性、版本稳定性、可复现性、许可、用户条件和核验兼容性，不自动选择最容易运行的一项。将差异和证据呈报用户；只有用户明确确认代码库、版本、目标模型或系统和改动范围后，才能完成开发基础契约。

没有确认开发基础时不得进入 `cvpr-plan`。不得让 `cvpr-plan` 代替用户或 `cvpr-goal` 选择代码库。

## 三、固化开发基础

将确认结果写入 `development_base`：

```yaml
project_state: existing_project | selected_repository
project_root: ""
repository_url: ""
repository_source: ""
repository_source_type: ""
branch: ""
commit: ""
version_or_snapshot: ""
target_model_or_system: ""
intended_change_scope: []
evaluation_compatibility:
  protocol_ids: []
  assessment: ""
  evidence_refs: []
user_confirmed: false
```

`repository_source` 记录可定位的来源说明，例如远程仓库、用户提供的本地项目或固定归档；不能只写“官方”或“现有项目”。Git 仓库优先记录 commit；分支只作为上下文，不能单独充当不可变版本。非 Git 项目必须提供可复查的版本号、快照或其他等效定位。`accepted` 或 `revised` 状态要求真实项目根目录可定位、来源清楚、版本可复查、改动对象与范围明确、评测兼容性有证据并且 `user_confirmed: true`。

## 四、建立评测映射

为每项主张建立：

```yaml
claim_id: CLAIM-001
research_claim: ""
expected_observable_change: ""
evaluation_object: ""
criterion_ids: []
counterevidence: ""
```

检查是否存在以下错位：

- 局部指标被用于支持整体系统主张；
- 仿真结果被用于支持真实环境主张；
- 平均结果掩盖关键子群或失败场景；
- 模型裁判结果被直接当成人类偏好；
- 相关性结果被用于支持因果机制；
- 单次运行被用于支持稳定性主张。

## 五、形成和确认草案

先展示开发基础候选和评测映射，再展示数值目标。用户可以修改代码库选择、改动对象、主张范围、验证载体、目标值或必需性。

只有用户明确说出接受、确认或等价表达，才将 `user_confirmation.status` 写为 `confirmed`。

## 六、执行边界

本 Skill 可以读取项目、论文、仓库和既有结果，形成核验契约。需要下载大型数据、运行高成本基线、控制机器人、发起付费评测或修改研究代码时，先建立独立原子任务并取得相应授权。

缺少实测基线不自动阻断所有目标：可以使用有来源的官方或用户基线，但必须保留来源类型和证据。无法据此确定可靠目标时维持 `proposed`。
