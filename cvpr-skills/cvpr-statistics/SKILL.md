# CVPR 实验统计

## 定位

只处理实验数据和统计证据。保持原子化、可重复调用，不拥有 Goal 判定权，不替 `cvpr-result` 或论文写作生成研究结论。

不固定某种指标、运行次数或显著性检验。统计方法必须由当前研究设计、实验单位、数据分布和 Goal 的证据要求决定。

## 调用模式

- `audit_recompute`：为 Result 审稿复算关键数字；
- `result_processing`：三审确认通过后生成用户呈报数据；
- `paper_update`：论文写作期间从同一审核结果更新表格组织或统计表达。

`paper_update` 不允许偷偷加入新的实验运行。需要新运行时返回 `cvpr-do`，形成新结果快照后重新复核。

## 工作流

### 1. 锁定输入

读取冻结快照、Run 账本、原始输出、配置、指标定义和协议。列出全部候选 Run，并为每个 Run 明确纳入或排除状态。

不直接使用人工复制的最终数字代替原始结果。只有汇总表而没有可定位原始证据时，标记阻断或限制。

### 2. 明确实验单位

根据研究设计确定独立单位，例如：

- 独立训练 seed；
- 数据样本、序列或任务；
- 仿真场景或 episode；
- 设备运行或物理实验；
- 人类评价者或评价项目；
- 模型、环境或系统实例。

不能把大量相关样本错误当成独立重复，也不能把不同 seed 与同一模型的多个 batch 混为一种单位。

### 3. 核对完整性

检查输入 Run 的完整性、重复、失败、缺失、条件一致性、指标字段、单位、样本量、数据划分和配置对应关系。每个候选 Run 必须被纳入或有证据地排除。

不得因为结果不利而排除。异常值、失败运行和缺失值按 [完整性、异常与选择规范.md](references/完整性、异常与选择规范.md) 处理。

### 4. 重算指标

使用稳定代码从原始结果计算。处理逻辑保存到：

```text
cvpr_workspace/analysis/statistics/
```

配置和规则保存在版本化文件中，禁止只用 notebook 未执行状态、`python -c` 或一次性 CLI 完成关键统计。

### 5. 选择统计方法

从研究设计、数据分布、配对关系、实验单位和 Claim 需求选择方法。不要默认要求：

- 固定三次或五次运行；
- 固定 t 检验；
- 必须有 p 值；
- 所有任务重复训练；
- 用均值和标准差描述所有分布。

需要说明方法、假设、适用对象、不确定性、效应量和多重比较处理。证据不足时如实输出限制，不自动降低标准。

### 6. 生成结果包

默认输出到：

```text
cvpr_workspace/result_package/
├── data/
├── tables/
└── statistics/
```

输出包括适用的结构化数据、主结果表、baseline 表、消融表、稳健性表、失败结果表和统计记录。每个数字能够追溯到 Run、原始文件、计算代码和配置。

以 [统计任务模板](assets/统计任务模板/statistics.yaml) 登记任务，并运行：

```bash
python3 <cvpr-statistics-Skill目录>/scripts/validate_statistics_manifest.py \
  <statistics.yaml> --project-root <项目根目录>
```

## 硬性边界

- 不修改原始结果；
- 不删除不利运行；
- 不自动处理异常值；
- 不按结果选择统计方法；
- 不改变指标定义、数据划分或 evaluator；
- 不声明 Goal 通过；
- 不把统计显著性等同于实际价值；
- 不撰写论文 Claim 或讨论；
- 不在图形中重新计算另一套数字。

## 完成标准

- 输入快照和全部候选 Run 可定位；
- 实验单位、纳入、排除、缺失、失败和异常规则明确；
- 所有输入 Run 均已纳入或有证据地排除；
- 指标和统计方法与研究设计一致；
- 关键处理由稳定代码执行；
- 结果表、统计文件和追溯信息完整；
- 没有 Goal 或论文结论越权；
- 统计任务契约校验通过。
