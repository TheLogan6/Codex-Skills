# 完整性、异常与选择规范

## 全量覆盖

每个输入 Run 必须：

- 纳入统计；或
- 以明确理由、规则和证据排除。

纳入与排除集合必须互斥，合并后恰好覆盖输入 Run。

## 失败运行

失败运行不能直接删除。先判断：

- 方法本身失败；
- 环境或基础设施失败；
- 数据或协议错误；
- 用户中止；
- 输出损坏；
- 原因不明。

如果失败率本身反映方法稳定性，应进入结果。基础设施故障可以排除，但需保留记录和证据。

## 缺失值

说明缺失发生在：

- 整个 Run；
- 某项指标；
- 某个样本或场景；
- 某个评价者；
- 某个配置。

不能把缺失默认为零，也不能只按对方法有利的方式删除。插补只有在研究设计允许且规则明确时使用。

## 异常值

先检查异常是否由解析、单位、重复、数值不稳定或真实长尾产生。处理前固定规则，记录原始值和敏感性结果。

禁止：

- 看见结果后选择阈值；
- 只删除目标方法的不利点；
- 用均值平滑隐藏不稳定；
- 删除失败 seed 后声称稳定。

## 选择偏差

检查：

- 只报告最佳 checkpoint；
- 只报告最佳 seed；
- baseline 与本方法调参预算不同；
- 根据测试集选择配置；
- 只展示成功场景；
- 只选择有显著差异的指标；
- 重复试验后只保留有利批次。

发现选择偏差时停止形成正式统计结果，并返回证据修复。
