# 问题状态复查规范

## 状态定义

- `solved`：在问题原有或更严格条件下，有多项独立证据表明失败现象被稳定消除，并有合理反证检查。
- `partially_solved`：只解决问题的一部分、部分指标或部分场景。
- `conditionally_solved`：在特定数据、模型、预算、硬件或假设下解决，条件外仍存在。
- `redefined`：后续工作改变了问题定义或评测方式，不能与原问题直接等同。
- `unresolved`：近期直接证据仍观察到问题，现有方案未稳定消除。
- `amplified`：新模型、数据或使用场景使问题影响更明显或更重要。
- `conflicting`：合格证据结论相反，现有材料不足以解释差异。
- `insufficient_evidence`：无法形成可靠判断。

## 证据矩阵

```yaml
problem_id: P-001
search_cutoff: YYYY-MM-DD
supporting_papers: []
counterevidence_papers: []
proposed_solutions: []
remaining_failure_conditions: []
comparability_notes: []
status: unresolved
status_rationale: ""
analyst_inference: ""
next_verification: ""
```

## 判定规则

- 不按论文数量简单投票；
- 优先比较直接实验、独立复现、严格对照和与目标条件最接近的证据；
- 不把排行榜增益、引用次数或作者自称“解决”作为单独依据；
- 若条件不可比，状态至少降为 `conditionally_solved` 或 `conflicting`；
- 任何 `solved` 判定都必须主动寻找失败案例和反证。
