# 模型组件内部计算图

围绕一次局部计算，展示输入如何被变换成输出。以 Engram 图为方法样例，迁移到新组件时重新推导所有算子、形状和共享关系。

## 先拆算法

读相关正文、公式、原图和指定版本实现。固定一个观察切片，例如“单 token、单模块，省略 batch”。写清外部输入、持久参数、临时中间量、返回值；组件边界外只保留必要上下文。

将公式拆成操作链，并建立张量表：名称、shape、来自哪个操作、是否广播/共享、被谁消费。优先用符号 n、d、k 表达泛化逻辑，再代入本模型数值。shape 未知则标符号，不能继承样例的 4 和 5120。

重点找出真正解释机制的几步：

- lookup 地址如何得到，取出的是什么；查表和搜索 Attention 的对象不同。
- concat 沿哪个维度，linear 改变哪个维度，split 的各段大小是什么。
- gate 是标量、向量还是矩阵；每分支独立还是全体共享。
- 同一张量广播到多路，还是分别生成多个张量。
- multiply 是逐元素、矩阵乘、外积或标量缩放；add 是否有合法广播。

## 从算子链变成图

1. **左侧加工链**：按真实依赖画 lookup/投影/拆分等步骤，给步骤短标题。不是所有组件都需要这三步。
2. **中间展开分支**：分支数量少且重要时全部画出；很多分支用两个代表分支加省略号与 n 标注。共享量画成一条带分叉点的总线。
3. **右侧重新组合**：用堆叠行或括号明确输出张量，不把“广播到多路”画成 concat。
4. **底部局部公式**：用 A/B/C 或相同颜色把算子位置与详细公式对应。虚线是解释引线，实线是数据流，明确图例。

参考 [Engram 分析与生成提示](references/source-and-prompt.md)，需要视觉参考时打开链接图片。允许采用其他适合该算法的布局；用户只要求一个步骤时只展开该步骤。

## 图上的文字和形式

标题写计算链，例如“查表 → 投影 → 门控 → 残差更新”。副标题写观察范围，避免把单 token 示例误解成完整 batch 布局。

默认以蓝色表示分支 key/投影、橙色表示共享 value/缩放、绿色表示更新结果、灰色表示原残差。为算子和张量加明确名称；新模型若不存在 key/value，改用真实角色，不能沿用误导标签。

将短 shape 放在张量旁，较长公式放下方。推导与权重存储朝向若不同，分开标注，例如数学 `eW` 与框架 Linear 的 `[out,in]` 存储；不要为排版把矩阵随意转置。

## 实际出图与验收

生成前准备准确可见文案、节点列表、带语义的边和形状推导。用户偏好 AI 绘图风格时用可用的图像生成工具及参考图；需要可编辑、精确数学或多次改字时采用 SVG/原生形状。遵守工具的参考图读取规则，不假定参考图代表正确的新模型参数。

打开成图，以一个输入走到输出，并逐个核对分叉、shape、公式及字符。图过密时优先减少非关键文字或拆成“流程 + 推导”两张，而非缩小至不可读。检查完成后交付图、读图说明、依据与已标明的简化；可编辑源文件如有则提供。

验收需能回答：每一路新增的信息来自哪里，门控到底输出几个数，相乘对象是什么，输出 shape 为什么成立。以 Engram 为例，要能看出各路 key 不同、共享 value 相同、每路门控各自计算；这些关系必须来自新任务证据，不能一律套用。
