# Engram 样例与提示词

打开 [Engram 内部计算参考图](engram.png)，对应用户所给技术报告第 8.1 节、DOCX 媒体 image8.png。以下均为该材料内的解释，未独立审计最新模型实现；原始图像生成提示词未保存在文档中。

## 这张图如何帮助理解

左侧将“查表”展开为三种 n-gram、每种 8 个 heads、每条 256 维，合成 6144；再投影到 25600 并分为 20480 + 5120。抽象模块因此变成可复算的数据变换。

中间把四路 key 与四路 residual 配对，各进入自己的 gate；橙色 value 总线只有一条，分叉到四个乘法节点。灰色 residual 绕过 gate，进入绿色加法节点。读者不用猜 key、value 和 residual 的对应关系。

底部 A、B、C 分别展开“怎么算 gate”“gate 怎样缩放 value”“结果怎样加回 residual”；引线只关联说明，不表示新一次计算。

## 维度推导与边界

```text
e: [1, 6144]             3 × 8 × 256
W: [6144, 25600]         数学右乘方向
z = eW: [1, 25600]
K: [4, 5120]            z 的前 20480 维 reshape
v: [1, 5120]            z 的后 5120 维
H: [4, 5120]
g: [4, 1]               每路匹配得到一个 gate
ΔH = gv: [4, 5120]      外积，每路按自己的 gate 缩放同一个 v
H' = H + ΔH: [4, 5120]
```

每路匹配使用归一化的 h、k 点积，除以 sqrt(d)，再经保留符号平方根和 sigmoid。参考图省略数值稳定项；若要求代码精度，应读取相关实现后补齐。

框架 Linear 的权重存储可能是 `[25600,6144]`，与数学右乘 W 的方向不同，参考图明确同时说明两者。

本材料中的 Engram key/value 属于门控模块，不是 Attention KV Cache；查表对象是训练得到的嵌入行。该版本无短卷积，且仅文本位置参与、n-gram 不跨图像边界。这些是版本事实，不能推广为所有 Engram 或所有记忆模块的性质。

## 迁移检查

若新组件是 `y=x+W_up(g⊙W_down x)`，其中 `x∈R^{d×1}`、`W_down∈R^{k×d}`、`g∈R^{k×1}`、`W_up∈R^{d×k}`，图要在 k 维处画逐元素门控，再升维并残差相加。不能复制 Engram 的查表、四路 key 或共享 value，也不能把向量 gate 画成一个标量。
