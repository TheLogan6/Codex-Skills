# 多路残差与执行时序图

让读者同时看懂“有几路状态”“重计算子层执行几份”“混合系数什么时候可用”。将空间中的张量数据流和时间上的系数依赖分开画，再以明确接口关联。

## 推导空间结构

从材料中确认状态排布、混合矩阵方向和操作顺序。若采用样例的行向量记法：`X:[n,d]`，`A:[1,n]` 将多路合成一条，`u=AX:[1,d]`；子层 `v=F(u):[1,d]`；`B:[n,n]` 混合残差，`C:[n,1]` 把子层输出分配回多路，`Y=BX+Cv:[n,d]`。

这只是读图约定，源公式采用转置约定时以源为准。核对每次矩阵乘是否成立；不为迁就样例而改变算法。若材料对 B 有双随机等约束，解释稳定性时标出其约束及来源；只解释数据流时可省略约束细节并说明范围。

若同时包含 Engram 或其他注入模块，先画 `X→X̃` 的更新，再画同一份 `X̃` 如何进入子层。明确注入沿用已有残差流；独立命名 Engram 的 gate 和 value，避免与 mHC 的 A/B/C、子层输出混淆。

## 推导时间依赖

从具体实现或公式确认：哪个子块产生 A、哪个子块消费 A，B/C 从什么状态得到，第一步如何初始化（若材料未说明则标“初始化未展开”）。区分 Transformer block 和 Attention/FFN 子块。

Single-Pass 等优化需要画对照：原顺序中哪些步骤必须等当前状态生成系数，优化后哪些系数已由前一子块提供。不要将“提前产生系数”直接翻译成“当前状态不再读取”。实际传递的是系数还是张量，箭头上直接写出来。

## 三段布局

按任务范围选择其中一段或组合，不要求每次都有三段：

1. **注入段**：画已有 n 路状态、外部新增内容和 gate，得到仍为 n 路的更新状态。
2. **子层段**：左 n 路 → A 合成 1 路 → F 一个盒子 → C 写回 n 路；B 残差旁路沿顶部绕行并接到最终加法。只有算法确实多次调用 F 时才画多个 F。
3. **时序段**：前一个子块 → 当前 Attention → 当前 FFN，系数传递单独着色、标产生者和消费者；与状态流使用不同图例。

参考 [mHC 与 Engram 样例及提示词](references/source-and-prompt.md)。沿用深蓝文字、浅色区域、灰色残差旁路；橙色强调系数，紫色强调实际子层运算，绿色表示写回结果。颜色以角色为准。

## 生成与复核

出图前写清节点、连线含义、张量形状、每个系数的产生/消费时机，以及一条读图结论。用户喜欢 AI 解释图时可给可用的图像生成工具提供参考图和准确图稿；公式密集或要求可编辑时优先 SVG/原生形状。简单时序可用 Mermaid。

实际查看成图，检查原残差是否正确绕过 F、合并是否真的从 n 到 1、F 的次数、写回是否恢复 n 路、系数线是否被误读成状态线。数学标签、上下标、乘加和矩阵维度逐项核对。附交付图、读图顺序、来源与范围说明；有编辑源时一起提供。

关于“省多少”的文字需要同口径依据：mHC 激活处理链的访存节约，不自动等于全模型访存、FLOPs 或延迟同比降低。n 路残差不自动意味着 n 份模型或 KV Cache 乘 n。没有实测或可复算依据时只表达依赖变化，不画虚构百分比。
