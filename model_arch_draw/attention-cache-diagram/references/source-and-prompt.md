# Attention 样例与提示词

来源是用户所给技术报告第 4 节。打开 [跨层复用解释图](layer-reuse.png)；其 DOCX 媒体项为 image4.png，生成工具与原提示词不可从文档确定。另有第 4.1 节和 4.3 节分别标为官方 Figure 4、Figure 5 的图；这里保留 [分层索引参考图](hierarchical-index.png)，来源身份以文档图注为准。

## 三层叙事

1. 顶部用一条黄色带声明大家共享 C，固定“同一请求、同一 token t”。这是比较条件。
2. 中间以 L21 Full、L22–24 Reuse、L25 Reindex 三列展开。Full 创建 C 并选择 I；Reuse 沿用 I；Reindex 用新 query 重新得到 I。每列都以 `S=C[I]` 收束。
3. 底部抽出所有层共同保留的计算：自己的 Q、自己的 SWA 和选中的 S，进入 concat 与 Attention。结论解决“Selected KV 相同是否输出也相同”的误解。

这个结构适合任何“共享部分资源、保留局部计算”的算法；不要把三种模式的名称强加给没有这些模式的模型。

## 样例事实与简化范围

材料中 L21 创建 Decoder 的主 KV 和 Index K，并生成候选池；L25、L29、L33、L37 从该池重新选点。第 4 节文本流程中的 `L239/L32` 等笔误，与紧邻正文及附录 A 不一致，应采用多处一致的 L25/L29/L33/L37，并在分析记录中指出。

候选池上限 `2048 blocks × 8 positions = 16384 positions`，最终全局选点最多 512；局部窗口 128 独立。后续主 Attention 的输入不是整个候选池。

图中简化 Attention 公式省略 sink、RoPE 和输出投影，图上已有说明。迁移时若解释精确 Attention 计算，需按新材料补齐；不要将此公式当作所有模型的精确实现。

`Full` 在这里表示创建缓存并选点，不是 dense attention；`Reuse` 在这里是同 token 的跨层复用，不代表下一 token 永远沿用旧位置。

## 迁移检查

输入材料若只有 GQA 的 8 个 Q heads 共享 2 组 K/V，图应表现 head 分组与对应关系，不能产生跨层 Full/Reindex/Reuse 或 Top-K。材料若只给候选集合，不能猜最终选择预算。
