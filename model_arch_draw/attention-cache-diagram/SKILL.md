# Attention 与缓存机制图

把“历史数据是什么”“选了哪些位置”“当前层实际算什么”拆成可见对象，再用依赖连接。先确定材料描述的算法、模型版本和执行阶段；普通 Attention 不必硬套索引器、候选池或共享缓存。

## 建立对象与归属

按需要写下以下对象的来源、形状、生命周期和消费者：本层 Main Q、K/V 或共享 latent、本层局部窗口、Indexer Q/K、候选位置集合、Top-K 位置清单、gather 后的内容、Attention 输出。

必须区分：

- **值与地址**：位置列表是整数地址；Selected KV 是取回的张量。Top-K 应先连到选择操作，不能直接冒充 KV 值。
- **对象与 owner**：多个层读同一份缓存，不表示多个层各产生一份；选点源也不必等于 KV 源。
- **跨层与跨时间**：固定同一 token 位置比较层间复用；若跨 token 复用，必须另有证据。写在副标题里。
- **索引 Q 与主 Q**：检索用的 Query 和 Attention 使用的 Query 分开命名。
- **计算与存储**：省掉索引或缓存创建不等于省掉当前层 Attention。

证据矛盾时记录到图稿说明；优先以指定版本和明确实现为依据，不能静默拼接不同算法。只解释所给文档时标为“据所给材料”。

## 根据问题选图

**模式对照**：用对齐的两列或三列，各列沿相同顺序画缓存、选点和取值。共同的本层计算可放在底部公共区。上方画共享数据总线，复用清单用独立线型，不能和共享 KV 合成一根无标签箭头。

**一次 Attention**：画 `Q + 可见 K → scores → mask/normalization → 加权 V → output`，按该模型真实顺序添加位置编码、压缩、量化或输出投影。稀疏选择放在主 Attention 之前；省略公式项时说明范围。

**分层索引**：用历史位置小格、候选块外框和最终被选位置三个层次。粗选与细选分开；首个索引层的“自己用的 Top-K”和“给后续层的候选池”画两条输出。

参考 [样例、边界与提示词](references/source-and-prompt.md)，需要复现视觉风格时打开链接图片。

## 让机制能被读出来

模式对照可用绿色表示本层新算、黄色表示复用的数据、橙色表示复用的位置列表，蓝色表示普通计算区域。加文字图例；颜色语义只在本图内成立。

用一个很小且明确标为“示例”的位置集合展示差异。例如 Reuse 保持 `{5,20,100}`，Reindex **可能**变成 `{5,30,200}`。这些集合不表示真实 Top-K 数量，重选结果也不保证每次不同。

公式贴到相应操作附近：`I = TopK(scores)`、`S = C[I]`、`local + selected → Attention`。不能用一个长公式替代分叉、共享和 gather。若局部与全局存储相同原始位置，不擅自按 token 去重：看实际槽位/表示语义。

## 绘制、检查、交付

先形成可核对的节点/边/标签图稿。可用图像生成工具配合参考图还原解释图风格；可编辑或公式密集的输出适合 SVG/原生形状。简单依赖也可使用 Mermaid。按用户格式与可用工具选择，不要求安装特定绘图服务。

实际打开生成结果，检查每根输入线、索引/值的身份、共享总线的分支、上下标和集合包含关系。在目标显示尺寸看文字；过密就分图。交付成图、短读图说明、所用来源和简化范围；如有可编辑源也提供。

检查以下机制不变量：

- 每个输出都有本层 Q 和正确的可见 K/V 输入。
- Reuse 不凭空出现索引重算；Reindex 不凭空创建主缓存。
- 最终选点属于允许搜索域，因果 mask 和短历史不会因示意图消失。
- 压缩率、候选数量、最终 K、窗口长度分别有单位与上限。
- 缓存字节数如进入图中，计入 scale、owner 数，区分缓存条目与原始 token；不能由概念图推断物理显存。
